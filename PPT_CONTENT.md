## Slide 6: System Architecture & Workflow
*(Tip: Add a simple flow chart diagram on this slide)*
*   **1. User Input:** User logs in via Clerk and submits a claim on the Next.js frontend.
*   **2. API Call:** The frontend sends an HTTP POST request (via Axios) containing the statement and user email to the Flask backend.
*   **3. Processing:** Flask formats the prompt and queries the Google Gemini API.
*   **4. Storage:** Flask saves the user's email, claim, and the AI's response into MongoDB.
*   **5. Output:** The AI's structured response is sent back to the frontend and displayed to the user.

### 💡 Speaker Notes / Tips for Presentation:
1.  **Don't just read the slides:** Use the bullet points as prompts. Explain *why* you did something, not just *what* you did.
2.  **Highlight Prompt Engineering (Slide 7):** Professors love this. Emphasize that you didn't just plug in an AI; you *engineered* the prompt to constrain the AI's output into a usable format for your app.
3.  **Highlight Data Isolation (Slide 10):** Explain exactly how you used the email from Clerk to filter the MongoDB queries. It shows a strong understanding of security.
4.  **Highlight Deployment (Slide 11):** Mentioning CORS and Environment Variables shows you understand real-world production issues, which is highly impressive for a student project.
5.  **Live Demo:** If allowed, keep the PPT to 5 minutes and spend the rest of the time showing the actual app working. A working demo is worth a thousand slides.
